# Redis instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `<Redis command>` (or `redis.search` / `redis.create_index`; the database index as a string, e.g. `0`, when no command args) | CLIENT | `db.statement` or `db.query.text`; `db.redis.args_length`; `db.system` or `db.system.name`; `db.redis.database_index` (legacy and `database/dup` modes only; no new-mode replacement); `net.peer.name` or `server.address`; `net.peer.port` or `server.port`; `net.transport` or `network.transport`; `redis.create_index.index`, `redis.create_index.fields` (FT.CREATE); `redis.search.index`, `redis.search.query`, `redis.search.total`, and dynamic `redis.search.xdoc_<document>.<field>` attributes (FT.SEARCH) | Spans are emitted for synchronous/asynchronous, cluster, and immediate command execution when instrumentation is enabled. Legacy/new database and HTTP attribute names are selected independently by `OTEL_SEMCONV_STABILITY_OPT_IN` (`default`, `database`, `database/dup`; HTTP values `default`, `http`, `http/dup`). Unix-socket connections emit the peer path and transport; TCP connections emit host/port and transport. An explicit `db=None` connection kwarg (e.g. from `from_url`) is reported as `db.redis.database_index=0` instead of being omitted. |
| `<space-separated Redis commands>` (or `redis` for an empty/invalid pipeline) | CLIENT | `db.statement` or `db.query.text`; `db.redis.pipeline_length`; `db.system` or `db.system.name`; `db.redis.database_index` (legacy and `database/dup` modes only; no new-mode replacement); `net.peer.name` or `server.address`; `net.peer.port` or `server.port`; `net.transport` or `network.transport` | Emitted for synchronous/asynchronous pipelines and cluster pipelines. On redis-py 6+ `ClusterPipeline`, queued commands are read from the execution strategy, so the span name, statement, and `db.redis.pipeline_length` reflect the queued commands instead of being empty (`redis`, `0`). Attribute naming follows `OTEL_SEMCONV_STABILITY_OPT_IN` as above. |
