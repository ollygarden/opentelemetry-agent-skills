# JDBC

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| Database operation (derived from SQL; stable query summary when available) | CLIENT | Legacy: `db.system`, `db.name`, `db.user`, `db.statement`, `db.operation`, `db.connection_string`, `net.peer.name`, `net.peer.port`. Stable: `db.system.name`, `db.namespace`, `db.query.text`, `db.query.summary`, `db.operation.name`, `db.collection.name`, `db.stored_procedure.name`, `db.operation.batch.size`, `server.address`, `server.port`, `error.type`; opt-in `db.query.parameter.<key>` | Legacy is the default; `OTEL_SEMCONV_STABILITY_OPT_IN=database` selects stable conventions and `database/dup` emits both. SQL-derived attributes are conditional on parsed query and database metadata. Query parameter capture requires `otel.instrumentation.jdbc.experimental.capture-query-parameters` and disables query sanitization. |

Java agent datasource-connection spans are disabled by default and require `otel.instrumentation.jdbc-datasource.enabled`; they use the datasource class and `getConnection` for naming, with code attributes and available database metadata. `COMMIT` and `ROLLBACK` client spans require `otel.instrumentation.jdbc.experimental.transaction.enabled`; database naming follows the same semantic-convention selection.

## Metrics

| Metric name | Type | Unit | Attributes | Notes |
|---|---|---|---|---|
| `db.client.operation.duration` | Histogram | s | Attribute advice: `db.system.name`, `db.namespace`, `db.operation.name`, `db.collection.name`, `db.query.summary`, `server.address`, `server.port`, `network.peer.address`, `network.peer.port`, `error.type` (when available) | Only when stable database conventions are enabled (`database` or `database/dup`). Recorded for enabled statement/transaction instrumenters. The instrumenter passes extracted operation attributes; SDK attribute advice/views determine which are retained. |
