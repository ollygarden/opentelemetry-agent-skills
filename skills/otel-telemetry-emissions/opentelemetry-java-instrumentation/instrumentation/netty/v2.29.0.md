## Logs

| Log/event name | Attributes | Notes |
|---|---|---|
| `exception` span event | `exception.type`, `exception.message`, `exception.stacktrace` | On by default; see the note below the table. |
| `http.client.request.exception` (log record) | `exception.type`, `exception.message`, `exception.stacktrace` | Severity `WARN`; HTTP client spans and error-only `CONNECT` and `RESOLVE` spans. Off by default; see the note below the table. |
| `http.server.request.exception` (log record) | `exception.type`, `exception.message`, `exception.stacktrace` | Severity `ERROR`; HTTP server spans. Off by default; see the note below the table. |
| `exception` (log record) | `exception.type`, `exception.message`, `exception.stacktrace` | Severity `WARN`; fully enabled `CONNECT` and `RESOLVE` spans, and `SSL handshake` spans. Off by default; see the note below the table. |

`Instrumenter.end` records exception signals only when it receives a throwable. Span status `ERROR` is set independently of these signals, so an `ERROR` status without a throwable records neither the span event nor a log record. `otel.semconv.exception.signal.preview`, or the declarative `general.semconv_exception.signal.preview`, which takes precedence, selects the signals: `logs` records only the log record, `logs/dup` records both, and unset or any other value records only the span event. `SemconvExceptionSignal` reads the selection once at initialization, the declarative key from `GlobalOpenTelemetry`; a non-global `OpenTelemetry` passed to a library builder does not change it. Log records are emitted even for unsampled spans. The instrumentation passes a throwable when writing a client request or handling a server request throws, when the channel pipeline catches an exception during a client request or, with the Java agent, a server request, when a server response write fails, or when a `CONNECT`, `RESOLVE`, or `SSL handshake` operation fails. A response with an error status, such as `500`, passes none unless one of these cases applies.
