# Spring WebFlux

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `{http.request.method}` | CLIENT | `http.request.method`, `url.full`, `server.address`, `server.port`, `http.response.status_code`, `error.type`; optionally captured `http.request.header.<key>` and `http.response.header.<key>` | HTTP client span. Library scope: `io.opentelemetry.spring-webflux-5.3`; agent scope: `io.opentelemetry.spring-webflux-5.0`. Header capture is configured through request/response header selectors. |
| `{http.request.method} {http.route}`; `{http.request.method}` when no route matched (or the pattern is `/**`); `HTTP` for unknown methods | SERVER | `http.request.method`, `url.scheme`, `url.path`, `url.query`, `http.route`, `http.response.status_code`, `network.peer.address`, `network.peer.port`, `network.local.address`, `network.local.port`; optionally captured request/response headers | HTTP server span; configured experimental HTTP server telemetry can add experimental attributes. Library scope: `io.opentelemetry.spring-webflux-5.3`. |
| `{HandlerSimpleClassName}.{methodName}` for annotated handler methods; `{HandlerSimpleClassName}.handle` for other handlers (lambda class names truncated after `$$Lambda`) | INTERNAL | `code.namespace`, `code.function` (old code semconv, default) or `code.function.name` (stable code semconv) | Java agent controller/handler span, scope `io.opentelemetry.spring-webflux-5.0`; gated by `otel.instrumentation.common.experimental.controller-telemetry.enabled` (declarative `controller_telemetry/development`, default false). Stable code attributes require `OTEL_SEMCONV_STABILITY_OPT_IN=code` (`code/dup` emits both) or `otel.instrumentation.common.v3-preview=true`. |
