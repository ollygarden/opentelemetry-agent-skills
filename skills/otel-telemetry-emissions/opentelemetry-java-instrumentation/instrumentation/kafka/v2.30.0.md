# Kafka instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `publish {messaging.destination.name}` | PRODUCER | `messaging.system`, `messaging.destination.name`, `messaging.operation` (`publish`), `messaging.client_id`, `messaging.destination.partition.id` (on completion), `messaging.kafka.offset` / `messaging.kafka.message.offset` (on completion), `messaging.kafka.message.key`, `messaging.kafka.message.tombstone`, captured `messaging.header.*` | Offset uses stable/old messaging semantic-convention gates respectively; header attributes are opt-in via `otel.instrumentation.messaging.experimental.capture-headers`. |
| `receive {messaging.destination.name}` | CONSUMER | `messaging.system`, `messaging.destination.name`, `messaging.operation` (`receive`), `messaging.client_id`, `messaging.batch.message_count`, `messaging.kafka.consumer.group`, captured `messaging.header.*` | Receive telemetry is disabled by default; enable with `otel.instrumentation.messaging.experimental.receive-telemetry.enabled`. |
| `process {messaging.destination.name}` | CONSUMER | `messaging.system`, `messaging.destination.name`, `messaging.operation` (`process`), `messaging.client_id`, `messaging.destination.partition.id`, `messaging.message.body.size`, `messaging.kafka.consumer.group`, `messaging.kafka.offset` / `messaging.kafka.message.offset`, `messaging.kafka.message.key`, `messaging.kafka.message.tombstone`, `kafka.record.queue_time_ms`, captured `messaging.header.*` | `kafka.record.queue_time_ms` and `messaging.kafka.bootstrap.servers` are gated by `otel.instrumentation.kafka.experimental-span-attributes`; queue time is only present when the record has a timestamp. Offset uses stable/old messaging semantic-convention gates; headers are opt-in. Kafka Connect emits a batch process span with `messaging.batch.message_count` and links to each record; Kafka Streams emits the process span for each processed source record. |

## Logs

| Log/event name | Attributes | Notes |
|---|---|---|
| `exception` span event | `exception.type`, `exception.message`, `exception.stacktrace` | On by default; see the note below the table. |
| `messaging.send.exception` (log record) | `exception.type`, `exception.message`, `exception.stacktrace` | Severity `WARN`; send spans. Off by default; see the note below the table. |
| `messaging.receive.exception` (log record) | `exception.type`, `exception.message`, `exception.stacktrace` | Severity `WARN`; receive spans. Off by default; see the note below the table. |
| `messaging.process.exception` (log record) | `exception.type`, `exception.message`, `exception.stacktrace` | Severity `ERROR`; process spans, including Kafka Connect and Kafka Streams. Each log uses the scope of the instrumenter that emitted it. Off by default; see the note below the table. |

`Instrumenter.end` records exception signals only when it receives a throwable. Span status `ERROR` is set independently of these signals, so an `ERROR` status without a throwable records neither the span event nor a log record. `otel.semconv.exception.signal.preview`, or the declarative `general.semconv_exception.signal.preview`, which takes precedence, selects the signals: `logs` records only the log record, `logs/dup` records both, and unset or any other value records only the span event. Log records are emitted even for unsampled spans. The instrumentation passes a throwable to a send span when `send` throws or its callback reports an exception, and to a Kafka Streams or Kafka Connect process span when `StreamTask.process` or `SinkTask.put` throws; producer-interceptor send spans get none. It passes none to receive spans or kafka-clients process spans: a failed `poll()` creates no receive span, and an exception thrown while processing an iterated record is not passed to its process span.
