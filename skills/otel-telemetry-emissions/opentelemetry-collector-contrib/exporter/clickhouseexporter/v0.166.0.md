# ClickHouse Exporter

All Traces and Metrics rows come from core `exporterhelper` v0.166.0, the version this release's `go.mod` requires; the exporter creates no meter or tracer of its own. `exporter` is the configured exporter ID (for example `clickhouse`). The `sent` and `send_failed` metrics carry no `server.address`, `server.port` or `url.path`. `sending_queue` and `retry_on_failure` are enabled by default. Rows and logs for profiles need a profiles pipeline, which needs feature gate `service.profilesSupport` (alpha, disabled by default).

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `exporter/<exporter ID>/<signal>` | INTERNAL | `exporter=<exporter ID>`; `data_type=<traces\|metrics\|logs\|profiles>` | Created by exporterhelper for each export request (each flushed batch when batching). When queued, it is a child of the `exporter/enqueue` span; when batching merges several requests, it has no parent and links to each merged request's parent span instead. Sets `items.sent` and `items.failed`; errors set span status to ERROR. With `retry_on_failure` enabled (the default), span event `Sending request.` (`retry_num`) on every attempt, and `Exporting failed. Will retry the request after interval.` (`interval`, `error`) before each backoff, which exporterhelper also logs at INFO. |
| `exporter/enqueue` | INTERNAL | `exporter=<exporter ID>`; `data_type=<traces\|metrics\|logs\|profiles>` | Queue configured; for each queue offer. Span event `Enqueued item.`, or `Failed to enqueue item.` on failure (with `sending_queue.wait_for_result: true`, also when the export then fails); the span status is never set. |

## Logs

| Log/event name | Attributes | Notes |
|---|---|---|
| `insert traces` / `insert json traces` | `records`; `process_cost`; `network_cost`; `total_cost` | The `json` form when `json: true`. `records` is the span count. |
| `insert logs` / `insert json logs` | `records`; `process_cost`; `network_cost`; `total_cost` | The `json` form when `json: true`. `records` is the log record count. |
| `insert gauge metrics` / `insert sum metrics` / `insert histogram metrics` / `insert exponential histogram metrics` / `insert summary metrics` | `records`; `process_cost`; `network_cost`; `total_cost` | One per metric type that has data points in the batch. `records` is the data point count. |
| `insert profiles` | `records`; `process_cost`; `network_cost`; `total_cost` | `records` is the profile sample count. |
| `Skipped metrics with an unset or unsupported type` | `skipped_metrics`; `skipped_by_type`; `example_metric_names` | WARN, once per export attempt (repeated on retries) that contains metrics with no table for their type (an unset type); at most five example names. |
| `failed to close json traces batch` / `failed to close json logs batch` / `failed to close profiles batch` | `error` | WARN; native protocol only, when the insert stops before sending on an attribute marshal, conversion or resolution error and ending the INSERT also fails. The same warning for `traces`, `logs` and the metric types cannot fire: their only early exit is an append error, which already releases the connection. |

The `insert ...` messages are DEBUG, logged after each successful insert; `process_cost`, `network_cost` and `total_cost` are Go duration strings for building the rows, sending them, and both. For metric types `process_cost` also includes preparing the INSERT. The metric-type `insert ...` messages use the logger of the most recently started ClickHouse metrics exporter, so with several instances their component fields can name another instance. Lists the exporter's own data-path log messages; configuration, startup and shutdown messages are omitted. So are the `Can't find a suitable value ...` and `unsupported ValueType ...` fallback warnings, which no pdata value type reaches.
