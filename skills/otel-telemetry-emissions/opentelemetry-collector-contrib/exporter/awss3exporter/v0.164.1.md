# AWS S3 Exporter

All Traces and Metrics rows come from core `exporterhelper` v0.164.0, the version this release's `go.mod` requires; the exporter creates no meter or tracer of its own. `exporter` is the configured exporter ID (for example `awss3`). The `sent` and `send_failed` metrics carry no `server.address`, `server.port` or `url.path`. `sending_queue` and `retry_on_failure` are enabled by default.

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `exporter/<exporter ID>/<signal>` | INTERNAL | `exporter=<exporter ID>`; `data_type=<traces\|metrics\|logs>` | Created by exporterhelper for each export request (each flushed batch when batching). When queued, it is a child of the `exporter/enqueue` span; when batching merges several requests, it has no parent and links to each merged request's parent span instead. Sets `items.sent` and `items.failed`; errors set span status to ERROR. With `retry_on_failure` enabled (the default), span event `Sending request.` (`retry_num`) on every attempt, and `Exporting failed. Will retry the request after interval.` (`interval`, `error`) before each backoff, which exporterhelper also logs at INFO. |
| `exporter/enqueue` | INTERNAL | `exporter=<exporter ID>`; `data_type=<traces\|metrics\|logs>` | Queue configured; for each queue offer. Span event `Enqueued item.`, or `Failed to enqueue item.` on failure (with `sending_queue.wait_for_result: true`, also when the export then fails); the span status is never set. |

Detailed-level gating comes from the service's default views, so it does not apply when `service::telemetry::metrics::views` is set.

## Logs

| Log/event name | Attributes | Notes |
|---|---|---|
| `uploading object` | `bucket`; `key` | DEBUG, before each S3 upload: one object per export request, logged again on each exporterhelper retry. Not logged for a compression error, or for an empty marshaled payload, which uploads nothing yet counts as sent. With `resource_attrs_to_s3.s3_prefix` set, each prefix value is a separate export request, unless `sending_queue.batch` merges them again; the object then uses the first resource's prefix. |

Lists the exporter's own data-path log messages; configuration, startup and shutdown messages are omitted.
