# Failover Connector

The connector creates no meter or tracer of its own and emits no metric or span for the active priority level. With `sending_queue` enabled (the default), the factory wraps the connector in core `exporterhelper` v0.164.0, the version this release's `go.mod` requires, with no retry and no timeout. It then emits the exporterhelper spans and metrics below, with `exporter` set to the connector ID (for example `failover`). With `sending_queue` disabled, none of the Traces or Metrics rows are emitted.

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `exporter/<connector ID>/<signal>` | INTERNAL | `exporter=<connector ID>`; `data_type=<traces\|metrics\|logs>` | Created by exporterhelper for each export request (each flushed batch when batching). When queued, it is a child of the `exporter/enqueue` span; when batching merges several requests, it has no parent and links to each merged request's parent span instead. Sets `items.sent` and `items.failed`; errors set span status to ERROR. |
| `exporter/enqueue` | INTERNAL | `exporter=<connector ID>`; `data_type=<traces\|metrics\|logs>` | For each queue offer. Span event `Enqueued item.`, or `Failed to enqueue item.` on failure (with `sending_queue.wait_for_result: true`, also when the export then fails); the span status is never set. |

| `otelcol_exporter_send_failed_metric_points` | Counter | `{datapoint}` | `exporter`; `error.type`; `error.permanent` | Emitted for items the connector could not route (see below). `error.type` and `error.permanent` are included at detailed telemetry level. |
| `otelcol_exporter_send_failed_spans` | Counter | `{span}` | `exporter`; `error.type`; `error.permanent` | Emitted for items the connector could not route (see below). `error.type` and `error.permanent` are included at detailed telemetry level. |
| `otelcol_exporter_sent_log_records` | Counter | `{record}` | `exporter` | Emitted for log records that a priority level accepted. |
| `otelcol_exporter_sent_metric_points` | Counter | `{datapoint}` | `exporter` | Emitted for metric points that a priority level accepted. |

Detailed-level gating comes from the service's default views, so it does not apply when `service::telemetry::metrics::views` is set.

The `send_failed` counters record items the connector could not route. (1) `All provided pipelines return errors`: every level failed. From then on every request fails at once without trying any level, until a `retry_interval` tick (default 10m) lets the next request probe the levels again. For this error `error.type` is `_OTHER` and `error.permanent` is `false` whatever the downstream errors were, and the span status description is that message. (2) With `condition` set, a non-matching error from the active level, or from a higher-priority level during a probe, which then becomes active again. exporterhelper drops those items, or, with `sending_queue.wait_for_result: true`, returns the error to the upstream component.

## Logs

| Log/event name | Attributes | Notes |
|---|---|---|
| `Downstream error matched failover condition; moving to the next pipeline level` | `error`; `pipeline_level` | DEBUG. Emitted only when `condition` is configured, for each downstream error that matches it while routing (not while retrying higher-priority levels). `pipeline_level` is the 0-based index of the level that failed. Returning to a higher-priority level is not logged. |

Lists the connector's own data-path log messages; configuration, startup and shutdown messages are omitted.
