# AWS S3 Receiver

Spans and metrics come from core `receiverhelper` v0.164.0, the version this release's `go.mod` requires, with `transport=s3`. Each receive operation covers one S3 object, read either by time range (`starttime`/`endtime`) or from `sqs` notifications. Objects with an unrecognized key suffix, and objects that hit download, decompression and unmarshal errors, produce no span or metric. `format` is the suffix of the first `encodings` entry matching the key (after a trailing `.gz` or `.zst` is removed) when that extension decodes the signal, even over the built-ins (a `.json` entry records `.json`); otherwise `otlp_json` (`.json` keys) or `otlp_proto` (`.binpb` keys). For metrics, every `*_metric_points` value counts metrics, not data points: the receiver reports `MetricCount()`. The receiver takes each count after the next consumer returns, so a processor that drops items in place lowers it.

The refused/failed split follows feature gate `receiverhelper.newReceiverMetrics` (alpha, disabled by default). Disabled, every next-consumer error counts as refused. Enabled, an error counts as refused only when it is marked as a downstream error, which in a Collector happens only when feature gate `telemetry.newPipelineTelemetry` (alpha, disabled by default) is also enabled: the service then wraps the receiver's next consumer and marks every error as downstream. Otherwise the error counts as failed, with `outcome=failure`.

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `receiver/<receiver ID>/TraceDataReceived` | Internal | `transport`; `format`; `accepted_spans`; `refused_spans`; `failed_spans` | One per receive operation of the traces receiver. |
| `receiver/<receiver ID>/MetricsReceived` | Internal | `transport`; `format`; `accepted_metric_points`; `refused_metric_points`; `failed_metric_points` | One per receive operation of the metrics receiver. The counts are numbers of metrics. |
| `receiver/<receiver ID>/LogsReceived` | Internal | `transport`; `format`; `accepted_log_records`; `refused_log_records`; `failed_log_records` | One per receive operation of the logs receiver. |

Each span is a root span with error status when the next consumer returns an error. The receiver calls the next consumer with the read context, not the span's, so processor and exporter spans are not its children. Tracer scope is the configured receiver ID (for example `aws_s3`, or `awss3` with the deprecated type alias).

## Logs

| Log/event name | Attributes | Notes |
|---|---|---|
| `status` (OpAMP custom message) | `telemetry_type` (`traces`, `metrics` or `logs`); `ingest_status` (`ingesting`, `completed`, `failed`); `start_time`; `end_time`; `failure_message` | Time-range reads with `notifications.opampextension` set. Not a Collector log: an OTLP log record with body `status`, marshaled as OTLP protobuf and sent as OpAMP custom message `TimeBasedIngestStatus` for capability `org.opentelemetry.collector.receiver.awss3`. One `ingesting` per time step, then `completed`, or `failed` with `failure_message`. `ingesting` and `failed` records are timestamped with the time step being read, `completed` with `endtime`. `start_time` and `end_time` are the configured `starttime` and `endtime` in Unix nanoseconds. On shutdown mid-range the `failed` status is not delivered: the receiver has already unregistered the capability, so `Failed to send notification` is logged instead. |
| `Start reading telemetry` / `Finished reading telemetry` | `start_time`; `end_time` | INFO, time-range reads; at the start of the range, and once the whole range has been read without error. |
| `Reading telemetry` | `time` | INFO, time-range reads; once per time step (a minute, hour or day, derived from `s3downloader.s3_partition_format`). |
| `Finding telemetry with prefix` | `prefix` | DEBUG, time-range reads; once per time step, before listing. |
| `No telemetry found for time` | `prefix`; `time` | INFO, time-range reads; the time step's prefix listed no objects. |
| `Retrieved telemetry` | `key` | DEBUG, time-range reads; after each object is downloaded. |
| `Error reading telemetry` | `error`; `time` | ERROR, time-range reads. A listing, download, decompression, decode, tag-check or next-consumer error stops the whole read: no later time step is read. |
| `Context cancelled, stopping reading telemetry` | `time` | ERROR, time-range reads; the receiver shut down before the range finished, noticed between time steps. A shutdown during a step's requests usually logs `Error reading telemetry` with a cancellation error instead. |
| `Waiting for messages from SQS` / `Received messages from SQS` | none / `messageCount` | DEBUG, SQS mode; around each receive call. |
| `Error receiving messages from SQS` | `error` | WARN, SQS mode; the reader waits 5s and polls again. |
| `Direct parsing as S3 event failed, trying SNS format` | `error` (only when the body does not decode as an S3 event notification) | DEBUG, SQS mode; also for valid JSON without `Records` that is not an `s3:TestEvent`. |
| `Failed to parse message as SNS notification` / `Message is not a valid S3 notification` / `Failed to parse S3 event from SNS message` | `error` or `type` | WARN, SQS mode. The message is skipped without deletion, so SQS redelivers it after the visibility timeout. |
| `Failed to decode S3 object key, using original` | `key`; `error` | WARN, SQS mode; URL-decoding the notification's object key failed, so the raw key is used. |
| `Skipping object from different bucket` / `Skipping object not matching prefix` | `bucket`, `targetBucket` / `key`, `prefix` | DEBUG, SQS mode; the record does not match `s3downloader.s3_bucket` or `s3downloader.s3_prefix`. |
| `Processing new S3 object` | `bucket`; `key` | INFO, SQS mode; one per `ObjectCreated:*` record that matches `s3downloader.s3_bucket` and `s3downloader.s3_prefix`. |
| `Failed to get S3 object` | `bucket`; `key`; `error` | WARN, SQS mode; the `GetObject` request or the body download failed. The message is kept for redelivery unless the object no longer exists. |
| `Processing trace file` / `Processing metric file` / `Processing log file` | `key`; `format` | DEBUG; before each object is decoded. |
| `Unsupported file format` | `key` | WARN; the first `encodings` entry whose suffix matches the key (after stripping `.gz`/`.zst`) cannot decode this signal, or none matches, and the key ends in neither `.json` nor `.binpb`. The object is skipped as if processed (and tagged when `s3downloader.tag_object_after_ingestion` is set); in SQS mode the message is deleted unless another of its records fails. |
| `Failed to process S3 object content` | `key`; `error` | ERROR, SQS mode; a decompression, decode or next-consumer error. The message is kept for redelivery. |
| `Message not deleted due to processing failures, will be retried after visibility timeout` | `receiptHandle` | WARN, SQS mode; a record of the message failed. |
| `Failed to delete message from SQS queue` | `error` | WARN, SQS mode. |
| `Skipping already ingested object` | `key`; in SQS mode also `bucket` | INFO; `s3downloader.skip_ingesting_tagged_objects` is set and the object has tag `otel-collector:status` = `ingested`. |
| `Failed to check object tags` | `key`; `error`; in SQS mode also `bucket` | ERROR; the ingested-tag check failed. Time-range reads stop; in SQS mode the message is kept for redelivery. |
| `Object does not exist` | `bucket`; `key` | WARN, SQS mode; the ingested-tag check found no object; the record counts as processed. |
| `Tagged S3 object` / `Failed to tag S3 object` | `bucket`; `key`; on failure also `error` | DEBUG / WARN; `s3downloader.tag_object_after_ingestion` is set, so the receiver sets tag `otel-collector:status` = `ingested`. A tagging failure does not undo the ingestion. |
| `Failed to send notification` / `Failed to send notification after multiple attempts` | `error`; `attempt` / `max_attempts` | ERROR; an OpAMP `status` message could not be sent. |

Lists the receiver's own data-path log messages; configuration, startup and shutdown messages are omitted.
