# OTLP Receiver

For all four signals and both transports, a request with zero spans, data points, log records, or profile samples returns before the receiver operation starts: it emits no `*Received` span and no accepted/refused/failed or `otelcol_receiver_requests` measurement.

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `otlp/TraceDataReceived` | Internal | `transport`; `format`; `accepted_spans`; `refused_spans`; `failed_spans` | `transport` is the configured transport; `format` is `protobuf`; count attributes record the outcome. `refused_spans` and `failed_spans` semantics are controlled by feature gate `receiverhelper.newReceiverMetrics`. |
| `otlp/MetricsReceived` | Internal | `transport`; `format`; `accepted_metric_points`; `refused_metric_points`; `failed_metric_points` | `format` is `protobuf`; count attributes record the outcome. `refused_metric_points` and `failed_metric_points` semantics are controlled by feature gate `receiverhelper.newReceiverMetrics`. |
| `otlp/LogsReceived` | Internal | `transport`; `format`; `accepted_log_records`; `refused_log_records`; `failed_log_records` | `format` is `protobuf`; count attributes record the outcome. `refused_log_records` and `failed_log_records` semantics are controlled by feature gate `receiverhelper.newReceiverMetrics`. |
| `otlp/ProfilesReceived` | Internal | `transport`; `format`; `accepted_profile_samples`; `refused_profile_samples`; `failed_profile_samples` | Profiles are alpha stability. `format` is `protobuf`; count attributes record the outcome. The refused/failed semantics are controlled by feature gate `receiverhelper.newReceiverMetrics`. |
