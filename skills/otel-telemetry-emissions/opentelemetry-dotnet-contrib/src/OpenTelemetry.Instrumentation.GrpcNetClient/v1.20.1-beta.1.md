# GrpcNetClient instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| Trimmed `grpc.method` (e.g. `greet.Greeter/SayHello`); `grpc` when the method is `other` | CLIENT | rpc.system.name=grpc; rpc.method (`_OTHER` when the method is `other`); rpc.method_original=`other` when the method is `other`; server.address and server.port when request URI exists; network.peer.address and network.peer.port for IP hosts; rpc.response.status_code (canonical status name, e.g. `OK`) when the `grpc.status_code` tag is present; error.type (the status name) for any non-OK status | The span name is the activity `DisplayName`, which the instrumentation sets from the trimmed `grpc.method` tag (leading/trailing `/` removed) and then removes `grpc.method`; without that tag the `Grpc.Net.Client` activity keeps its own name. The activity operation name is set by `Grpc.Net.Client`, not this package. Existing `Grpc.Net.Client` activity is enriched when `Activity.IsAllDataRequested` and the request filter accepts it. The filter defaults to accept; `SuppressInstrumentation` and sampler decisions can prevent enrichment. The instrumentation assigns `OpenTelemetry.Instrumentation.GrpcNetClient` as the ActivitySource; the activity originates in `Grpc.Net.Client`. Request and response enrichment callbacks can add user-defined attributes. |
