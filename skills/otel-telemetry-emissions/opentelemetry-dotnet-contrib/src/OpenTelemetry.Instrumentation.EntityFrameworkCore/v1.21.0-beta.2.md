# Entity Framework Core instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| Database name from the connection; `db.query.summary` or `EXECUTE <procedure>` under new attributes | CLIENT | `db.system` / `db.system.name`, `db.name` / `db.namespace`, `peer.service` / `server.address`, `server.port`, `db.statement` / `db.query.text`, `db.query.summary`, `db.operation.name`, `db.stored_procedure.name`, `db.query.parameter.{key}`, `error.type`; conditional `ef.provider`; user enrichment tags | `OTEL_SEMCONV_STABILITY_OPT_IN` defaults to old `db.*` attributes; `database` selects new attributes; `database/dup` emits both. `server.port` and `db.query.parameter.{key}` require new attributes; query parameters additionally require `OTEL_DOTNET_EXPERIMENTAL_EFCORE_ENABLE_TRACE_DB_QUERY_PARAMETERS=true` (default false). The exported span name is `Activity.DisplayName`; the activity operation name is `OpenTelemetry.Instrumentation.EntityFrameworkCore.Execute`. Text commands are sanitized (and summarized) only for providers mapped to SQL Server, SQLite, MySQL, PostgreSQL, Oracle, Firebird, Spanner, Teradata, or Db2; other providers (Cosmos DB, MongoDB, Couchbase, unrecognized) emit the raw command text in `db.statement`/`db.query.text`. Command events without a `DbContext` also emit raw text, even when `db.system`/`db.system.name` is inferred from a known command type such as `Microsoft.Data.SqlClient.SqlCommand`. Stored procedures emit the command text as `db.statement` or `db.stored_procedure.name`/`db.operation.name=EXECUTE`. `db.query.parameter.{key}` values are raw, unsanitized parameter values. `ef.provider` is emitted only for unknown SQL providers under old attributes. `Filter` can suppress a command. Exceptions set status ERROR and `error.type` (exception type full name). |
