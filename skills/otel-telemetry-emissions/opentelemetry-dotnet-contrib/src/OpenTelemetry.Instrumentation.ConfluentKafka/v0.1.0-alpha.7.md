# Confluent Kafka instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `{topic} publish` | Producer | messaging.system, messaging.client_id, messaging.destination.name, messaging.operation, messaging.kafka.message.key, messaging.kafka.destination.partition, error.type | Created by every `Produce` and `ProduceAsync` overload; injects the span context into the message headers. The partition is set only by the `TopicPartition` overloads. On `ProduceException` or `ArgumentException` the span gets Error status and `error.type` (`ProduceException: {code}` or `ArgumentException: {paramName}`); other exceptions leave no `error.type`. |
| `{topic} receive` (or `receive` when the topic is unknown) | Consumer | messaging.system, messaging.client_id, messaging.destination.name, messaging.kafka.destination.partition, messaging.kafka.message.offset, messaging.kafka.consumer.group, messaging.operation, messaging.kafka.message.key, error.type | Created by the `Consume` overloads when they return a non-EOF result, and when they throw `ConsumeException`; a `null` result (timeout) creates no span. On `ConsumeException` the span gets Error status and `error.type` (`ConsumeException: {error}`), and topic, partition, offset and key come from the exception's consumer record, so they are omitted when it has none. Starts under the current activity and links to the context extracted from the message headers. |
| `{topic} process` (or `process` when the topic is unknown) | Consumer | messaging.system, messaging.client_id, messaging.destination.name, messaging.kafka.destination.partition, messaging.kafka.message.offset, messaging.kafka.consumer.group, messaging.operation, messaging.kafka.message.key, error.type | Created only by `ConsumeAndProcessMessageAsync` when it receives a non-EOF message; ordinary `Consume` calls do not create it. It checks only for a listener on the source, not the consumer's trace flag. Links to the message's propagated context. If the handler throws, the span gets Error status and `error.type` is the exception's full type name. |

Publish and receive spans require `AddKafkaProducerInstrumentation` or `AddKafkaConsumerInstrumentation` on the `TracerProviderBuilder`, which adds the `OpenTelemetry.Instrumentation.ConfluentKafka` source and turns on the trace flag of the `InstrumentedProducerBuilder` or `InstrumentedConsumerBuilder`; they are off otherwise. The process span needs only a listener on that source, so `AddSource("OpenTelemetry.Instrumentation.ConfluentKafka")` or `AddKafkaProducerInstrumentation` alone enables it without `AddKafkaConsumerInstrumentation`. `messaging.system` is `kafka` and `messaging.operation` is `publish`, `receive` or `process`. `messaging.kafka.message.key` is set only for a non-null key, and `messaging.kafka.consumer.group` only when the consumer config has a `GroupId`.

## Metrics

| Metric name | Type | Unit | Attributes | Notes |
|---|---|---|---|---|
| `messaging.publish.duration` | Histogram | `s` | messaging.operation, messaging.system, messaging.destination.name, messaging.kafka.destination.partition, error.type | For `Produce`, covers only the enqueue call, not delivery. |
| `messaging.publish.messages` | Counter | - | messaging.operation, messaging.system, messaging.destination.name, messaging.kafka.destination.partition, error.type | - |
| `messaging.receive.duration` | Histogram | `s` | messaging.operation, messaging.system, messaging.destination.name, messaging.kafka.destination.partition, error.type | - |
| `messaging.receive.messages` | Counter | - | messaging.operation, messaging.system, messaging.destination.name, messaging.kafka.destination.partition, error.type | - |

Metrics require `AddKafkaProducerInstrumentation` or `AddKafkaConsumerInstrumentation` on the `MeterProviderBuilder`, which adds the `OpenTelemetry.Instrumentation.ConfluentKafka` meter and turns on the builder's metrics flag; they are off otherwise. Publish metrics are recorded once per `Produce` or `ProduceAsync` call, including failed ones; they set the partition only for the `TopicPartition` overloads, and `error.type` matches the span value but is assigned only while a publish span exists, so with tracing off a failed publish is recorded without `error.type`. Receive metrics are recorded once per `Consume` call that returns a non-EOF result or throws `ConsumeException`; on `ConsumeException`, `error.type` is `ConsumeException: {error}` and destination and partition are omitted when the exception has no consumer record. Both histograms advise explicit bucket boundaries from 0.005 s to 10 s.
