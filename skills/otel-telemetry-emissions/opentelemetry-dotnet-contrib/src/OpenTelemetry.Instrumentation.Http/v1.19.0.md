# HttpClient instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| HTTP method (or `HTTP` for unrecognized method) | CLIENT | http.request.method, http.request.method_original (when method is normalized), server.address, server.port, url.full, network.protocol.version, http.response.status_code, error.type | Package-created on .NET Framework and package-enriched on runtimes before .NET 9; .NET 7+ uses the `System.Net.Http` runtime ActivitySource, and .NET 9+ supplies native HTTP span attributes. `RecordException` (default false) adds an exception event. Before .NET 9, the package sets `url.full` with the value after each `=` in the query replaced by `Redacted`; query components without `=` and the URL fragment stay unchanged; set `OTEL_DOTNET_EXPERIMENTAL_HTTPCLIENT_DISABLE_URL_QUERY_REDACTION=true` (environment variable or `IConfiguration` key) to disable that redaction. On .NET 9+, the runtime sets `url.full` and replaces the whole query with `*`; that redaction ignores the package setting and is disabled only by the runtime switch `System.Net.Http.DisableUriRedaction` or `DOTNET_SYSTEM_NET_HTTP_DISABLEURIREDACTION=true`. The `DisableUrlQueryRedaction` option property is internal and not settable by applications. |

## Metrics

| Metric name | Type | Unit | Attributes | Notes |
|---|---|---|---|---|
| http.client.request.duration | Histogram | s | http.request.method, server.address, url.scheme, server.port, network.protocol.version, http.response.status_code, error.type | Package histogram on .NET Framework and netstandard2.0 builds. On .NET 8+ builds, `AddHttpClientInstrumentation()` subscribes to runtime meters `System.Net.Http` and `System.Net.NameResolution`; those runtime-defined instruments and their attributes are outside this repository's emission implementation (Microsoft documents that the runtime histogram omits default-port `server.port` on .NET 8 but always includes it on .NET 9+). For the package histogram, response, protocol, status, and error attributes are conditional on response/error availability; server address and scheme require a request URI, and `server.port` is omitted for the default port. |
