# gRPC instrumentation

## Traces

| Span name | Kind | Attributes | Notes |
|---|---|---|---|
| `grpc.<service><method>` (the leading slash in the gRPC path is removed) | CLIENT | `rpc.system`, `rpc.method`, `rpc.service`, `server.address`, `server.port`, `rpc.grpc.status_code`, `grpc.error_name`, `grpc.error_message`; configured request/response metadata as `rpc.request.metadata.<key>` / `rpc.response.metadata.<key>` | `server.address` and `server.port` are derived from the client channel target when it matches the parsed host/port form. Status and error attributes depend on call outcome; metadata attributes require the corresponding capture configuration. Client spans are not created for methods matching `ignoreGrpcMethods`. |
| `grpc.<service><method>` (the leading slash in the gRPC path is removed) | SERVER | `rpc.system`, `rpc.method`, `rpc.service`, `rpc.grpc.status_code`, `grpc.error_name`, `grpc.error_message`; configured request/response metadata as `rpc.request.metadata.<key>` / `rpc.response.metadata.<key>` | Status and error attributes depend on call outcome; metadata attributes require the corresponding capture configuration. Server spans are not created for methods matching `ignoreGrpcMethods`. |
